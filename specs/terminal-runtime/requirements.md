# TUI-RUNTIME requirements

Every requirement this specification owns, with the proof that closes it. Delivery state and
public evidence for each ID are recorded in [`status.json`](status.json); this file defines what
each ID means. The design is in [`spec.md`](spec.md) and [`plan.md`](plan.md), the test contract
in [`test-spec.md`](test-spec.md), and the work order in [`tasks.md`](tasks.md).

| ID | Requirement | Verification |
|---|---|---|
| `TUI-RUNTIME-R001` | **Terminal operation client issues typed commands with pending approvals.** Agent-terminal-ui's client and commands modules validate an operation ID and JSON input against the installed generated Graph OS registry before invoking it, and surface an A2A approval exchange as pending rather than granting it locally; approval actions stay unavailable until the corresponding Graph OS contract is proven end to end. | Command and client unit tests plus negative approval tests confirm invalid operations are rejected and pending approvals are never silently granted. |
| `TUI-RUNTIME-R001.1` | **Known op and object params produce one versioned request with correct envelope.** Child slice of `TUI-RUNTIME-R001` (see tasks.md). | Unit command parser plus httpx.MockTransport. Installed generated registry artifact. Known op and object params produce one versioned request with correct envelope. Empty ID, malformed JSON, array input, unknown op, missing registry file and digest mismatch make zero effect requests |
| `TUI-RUNTIME-R001.2` | **Verified caller header reaches remote GraphOS only over TLS.** Child slice of `TUI-RUNTIME-R001` (see tasks.md). | Client transport with loopback and remote URLs, fake bearer. Verified caller header reaches remote GraphOS only over TLS. Remote HTTP, absent/invalid bearer, credential in exception/log/snapshot all fail |
| `TUI-RUNTIME-R001.3` | **One /confirm resumes exactly the issued plan.** Child slice of `TUI-RUNTIME-R001` (see tasks.md). | A2A fake server that issues a PLAN with binding and expiry. One /confirm resumes exactly the issued plan. Tampered op/input/digest/subject, expired plan and replay are rejected before any effect. Server also rejects stale lease |
| `TUI-RUNTIME-R001.4` | **Typed success renders and chat remains functional.** Child slice of `TUI-RUNTIME-R001` (see tasks.md). | Mock error envelope, timeout, disconnect and malformed JSON. Typed success renders and chat remains functional. Every failure renders an error, leaves session usable and never reports success |
| `TUI-RUNTIME-R001.5` | **Pending request is displayed. No effect is asserted.** Child slice of `TUI-RUNTIME-R001` (see tasks.md). | Pending A2A task with input-required and approval metadata. Pending request is displayed. No effect is asserted. Approvals., fleet grant, missing signed exchange and wrong pending-call binding are refused. Enabling approval requires separate served receipt |
| `TUI-RUNTIME-R001.6` | **Base chat works. Compatible optional install enables /op.** Child slice of `TUI-RUNTIME-R001` (see tasks.md). | Clean Python 3.11 base environment and supported optional-client environment. Base chat works. Compatible optional install enables /op. No compatible client yields clear CLIENT_UNAVAILABLE and no untyped fallback |
| `TUI-RUNTIME-R001.7` | **Legacy screens still render or use served replacement.** Child slice of `TUI-RUNTIME-R001` (see tasks.md). | Route/import inventory plus Textual pilot tests. Legacy screens still render or use served replacement. No agent_utilities.knowledge_graph import, duplicate transport or invisible command fallback |
| `TUI-RUNTIME-R002` | **Terminal chat transport is reconciled with the current Graph OS boundary.** Agent-terminal-ui selects and implements one canonical transport for its primary conversational connection to Graph OS in place of the unmounted streaming and remote-procedure routes it currently expects, updates its client to that transport atomically, and removes the superseded code path. | Session, authentication, streaming and cancel behavior against the chosen transport are proven by integration tests before the superseded path is removed. |
| `TUI-RUNTIME-R003` | **Packaged development skill carries the rapid-delivery contract.** Add `agent_terminal_ui/skills/agent-terminal-ui-development/SKILL.md`, shaped like agent-webui's skill, with the five-minute lane rules. | `tests/test_skill_package.py::test_development_skill_packaged` asserts the file ships in the wheel and names the lane rules. |
| `TUI-RUNTIME-R004` | **Pre-commit runs the spec and sprawl hooks agent-webui runs.** Add the `spec-standard`, `check-public-specs`, `ste-staged`, `check-root-hygiene` and `check-gitignore-convergence` hook ids to `.pre-commit-config.yaml`. | `tests/test_precommit_hooks.py::test_spec_hooks_present` parses the config and asserts each id. |
| `TUI-RUNTIME-R005` | **Docs layout matches agent-webui.** Add `docs/start.md`, `docs/status.md`, `docs/deployment.md` and `docs/design-system.md`, and list them in `mkdocs.yml`. | `tests/test_docs_layout.py::test_docs_pages_in_nav` asserts each file exists and appears in the nav. |
| `TUI-RUNTIME-R006` | **Pyproject configures the pipelines hook sections.** Add `[tool.pipelines_hooks.public_surface]` and `[tool.pipelines_hooks.ste]` with `specs` in `paths` to `pyproject.toml`. | `tests/test_precommit_hooks.py::test_pipelines_hook_sections` parses `pyproject.toml` and asserts both sections. |
| `TUI-RUNTIME-R007` | **Release workflow caller matches agent-webui.** Add `.github/workflows/release.yml` calling the shared pipelines release workflow at `main`. | `tests/test_docs_layout.py::test_release_workflow_calls_pipelines` asserts the `uses:` line. |
| `TUI-RUNTIME-R008` | **Terminal theme tokens and accessibility are a stated contract.** `agent_terminal_ui/app.py` selects a Textual theme by name. State the token set, contrast floor and a no-colour fallback, as the design-system area in agent-webui does. | `tests/test_app_handlers.py::test_theme_tokens_and_no_color_fallback` asserts the default theme and the fallback. |
| `TUI-RUNTIME-R009` | **AGENTS.md sections match agent-webui.** Add `Commands`, `Quality gates`, `Branching & isolation` and `Documentation` headings to `AGENTS.md`. | `tests/test_docs_layout.py::test_agents_md_headings` asserts the headings. |
| `TUI-RUNTIME-R010` | **Run harness surface is read-only and honest.** The agent-terminal-ui client must display a run's current plan, context use against budget, applied harness configuration, cost and termination reason. The client reads only graph-os operations. | Children TUI-RUNTIME-R010.1 to TUI-RUNTIME-R010.6. |
| `TUI-RUNTIME-R010.1` | **Run read goes through the graph-os read operations.** The client run view must read `runs.get` and `runs.metrics` (the `GRAPHOS-OPS` rows for run metrics). The client must not call the engine and must not compute these values. | `tests/x::test_run_read_uses_graphos_operations` |
| `TUI-RUNTIME-R010.2` | **Applied harness configuration is displayed.** The run view must display the run's `harness_config`: `context_policy`, `plan_scaffold` and `action_space`. A missing field must read "not available". | `tests/x::test_harness_config_shown` |
| `TUI-RUNTIME-R010.3` | **Context use is displayed against the budget.** The run view must display `peakContextTokens` against `contextBudgetTokens` and the cost `costUsd`. An absent field must read "not available", never zero. | `tests/x::test_context_and_cost_shown` |
| `TUI-RUNTIME-R010.4` | **Current plan is displayed read-only.** The run view must render the current plan from the run's plan state. The view must offer no edit control. | `tests/x::test_plan_read_only` |
| `TUI-RUNTIME-R010.5` | **Each termination reason has a distinct state.** The run view must map each `terminationReason` (`final_answer`, `context_overflow`, `stuck`, `step_budget`, `error`) to its own label. `context_overflow` and `stuck` must not appear as a generic failure. | `tests/x::test_termination_reasons_distinct` |
| `TUI-RUNTIME-R010.6` | **Absent operation displays an honest state.** When `runs.get` or `runs.metrics` is absent or refused, the run view must display "not available" and no fabricated value. | `tests/x::test_absent_operation_not_available` |
