# TUI-RUNTIME requirements

Every requirement this specification owns, with the proof that closes it. Delivery state and
public evidence for each ID are recorded in [`status.json`](status.json); this file defines what
each ID means. The design is in [`spec.md`](spec.md) and [`plan.md`](plan.md), the test contract
in [`test-spec.md`](test-spec.md), and the work order in [`tasks.md`](tasks.md).

## TUI-RUNTIME-R002 child requirements

| ID | Requirement | Verification |
|---|---|---|
| `TUI-RUNTIME-R002.1` | **Preserve original chat transport acceptance.** Model: The terminal uses one canonical transport for its primary GraphOS conversation. This replaces its expected unmounted streaming and remote-procedure routes. Behavior: The client changes atomically to the chosen transport. Remove old paths only after the original integration acceptance passes. Wiring: Extend the existing client and session entry. Refusal: Keep old paths until proof passes. Evidence: Serve session, authentication, streaming and cancellation cases. | Integration tests cover session, authentication, streaming and cancellation against the chosen transport. Remove superseded paths only after those tests pass. |
| `TUI-RUNTIME-R002.2` | **Validate the host receipt and scope.** Model: A version 1 HostLaunchReceipt binds host instance, interface mode, endpoint, session, workspace, readiness and opaque log reference. The server binds each read to tenant, principal, host, workspace, generation and expiry. Behavior: Validate receipt version and every binding before a log read. Wiring: Use GraphOS contracts GRAPHOS-HOST-R009.2 through R009.6 and R010.7. Refusal: Missing readiness, unsupported version, expired scope or changed binding yields zero reads. Receipt data alone never grants authority. Evidence: A matching served receipt succeeds. Alter each binding independently for negative cases. | A matching served receipt succeeds. Every invalid binding produces zero log reads. |
| `TUI-RUNTIME-R002.3` | **Define the terminal consumer adapter.** Model: The TUI defines one public adapter named agent_terminal_ui.app.run_host_terminal. It takes HostLaunchReceipt, AgentClient and an optional HostLogReader. Plan.md gives the exact type signature. Behavior: Borrow the injected client and reader. Read only the receipt's opaque authorized reference. Wiring: Reuse the application, client and MainScreen path. Refusal: Missing reader, reference or producer returns unavailable and makes zero reads. Do not add a route, router, gateway or filesystem reader. Evidence: Enter through the public adapter on the served terminal path. | A valid reference reaches the reader. A missing capability makes zero reads and reads no file path. |
| `TUI-RUNTIME-R002.4` | **Honor producer-selected modes and unify the log view.** Model: GraphOS selects terminal, web or both (combined) through R010.7. The TUI takes mode only from the authorized receipt. Behavior: Terminal and both modes subscribe to host records. Web mode creates no TUI subscription. The /logs command and Ctrl+V use the same view. Agent chat continues. Wiring: Reuse CommandProcessor.cmd_logs, MainScreen.action_toggle_logs and RichLog. Refusal: Local input cannot change authenticated mode or authority. Web mode makes zero reads. Render text literally and strip terminal controls. Evidence: Exercise all three modes through the real selector and UI. | Terminal and both modes render one correlated record through /logs and Ctrl+V during chat. Web mode makes zero TUI log reads. |
| `TUI-RUNTIME-R002.5` | **Enforce tenant scope and bound log lifecycle.** Model: HostLogBatch binds schema, scope, host, generation, tenant-local records, cursor and optional gap. Each record carries request correlation, sequence, timestamp, severity and redacted message. Behavior: Reauthorize every read and reconnect. Preserve order and report rotation gaps. Clear records and cursors after denial. Cancel the owned reader when the view closes. Wiring: Use one worker on the existing screen path. The adapter owns only subscription and view state. Refusal: Reject foreign, expired, revoked or regressing scopes and cursors. Never open a shared file, close a borrowed client or stop the host. Evidence: Observe per-tenant sequences, queue bounds, gaps, denial clearing and cancellation. Allow one read in flight and 128 records per batch. Limit each record to 16 KiB. Limit pending data to 128 records or 2 MiB. Keep 1000 rendered lines. Set one-second read and five-second cancellation timeouts. | Two tenants sharing one workspace receive only their own records and offsets. Rotation yields a gap. Denial clears state. Unmount cancels within five seconds. |
| `TUI-RUNTIME-R002.6` | **Prove the served consumer journey.** Model: Evidence names producer and consumer revisions, receipt version, tenant scope and fixture seed. Behavior: Exercise terminal, web and both modes on the actual GraphOS host and production TUI. Keep agent interaction available. Wiring: Use the normal request path, not an isolated helper. Refusal: Mocks do not prove served behavior. Denied workspace scope yields zero unauthorized reads. Slow rendering cannot block host HTTP. Evidence: Track request IDs, sequences, gaps, read counts, render time, HTTP response and revisions. Save no credentials or raw sensitive logs. | Seed 116117 creates two tenants with separate principals in one workspace. Each emits 128 unique request IDs. Repeat the fixture twice. Normalize timestamps. Compare per-tenant ordered IDs, sequences and gaps. Cover all modes, rotation, reconnect, revocation and denial. Keep request-to-render time below two seconds. Include a live HTTP response during slow rendering. |
